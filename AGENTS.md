# AI agent operating manual (R package side)

> This repository is the **R-package half** of an AI-native dissertation provisioned by [dissertation.ai](https://dissertation-ai.dataimago.ai). **Every AI tool reads this file** — Codex, opencode, Cursor, Copilot and others directly; Claude Code through `CLAUDE.md`.

## What this repo is

A standard R package shape with two responsibilities:

1. **Host the dissertation's methodological R code** in `R/` — usable from inside the dissertation, importable into other R sessions, R-CMD-check'd in CI.
2. **Host the Quarto book** at `ui/www/` that renders to the thesis PDF — same source renders to HTML and PDF; CI rebuilds the PDF on every push.

The `ui/www/` Quarto root follows the dataimago framework's convention for R packages that carry a book (see [dataimago](https://github.com/dataimago/dataimago)).

## Where things live

| Path | Purpose |
|---|---|
| `DESCRIPTION` | Package metadata. **Don't manually edit the version** — handled at release time. |
| `NAMESPACE` | Generated by `devtools::document()`; don't hand-edit |
| `R/` | Your methodological R code, roxygen-documented |
| `tests/testthat/` | Unit tests; new functions need a corresponding test |
| `man/` | Auto-generated roxygen docs |
| `ui/www/_quarto.yml` | Book config — chapters list, PDF format, fonts, citation style |
| `ui/www/chapters/*.qmd` | Per-chapter sources |
| `ui/www/thesis.cls` | LaTeX thesis class (see `ui/www/THESIS-CLS-README.md` for the 3-mode strategy) |
| `ui/www/dataimago.sty` | Companion LaTeX support (typography hooks) |
| `ui/www/references.bib` | BibTeX bibliography |
| `.github/workflows/build-thesis.yml` | Renders PDF on push; commits to `docs/thesis.pdf` |
| `.github/workflows/R-CMD-check.yml` | R CMD check on push + PR |

## When the user asks for help

- **"Edit chapter X"** — work in `ui/www/chapters/X.qmd`. Changes trigger `build-thesis.yml`.
- **"Add a citation"** — append a BibTeX entry to `ui/www/references.bib`; cite in chapter via `[@bibtex-key]`.
- **"Change thesis formatting"** — see `ui/www/THESIS-CLS-README.md`. For generated mode, read the institution's guidelines from the app repo's `raw/thesis-formatting/` and iterate on `ui/www/thesis.cls`.
- **"Add an R function for my methodology"** — create `R/<descriptive-name>.R`, roxygen-document, run `devtools::document()` locally, add a test in `tests/testthat/test-<name>.R`.
- **"Why does my thesis PDF look weird?"** — check the latest `build-thesis.yml` run; common issues: missing LaTeX packages (add to the `tlmgr install` line), Quarto YAML syntax errors, undefined references.

## The dataimago-spec.yaml is in the APP repo

The author's `dataimago-spec.yaml` lives in the **app repo** (the dissertation's other half; its address is at the top of `CLAUDE.md` and in `README.md`), not here. But its content drives how `_quarto.yml` substitutes values, what chapters exist, what the bibliography is configured for, etc. When the spec changes, the app repo's `generate.yml` workflow runs `dataimago::ai(spec_path)` which may push changes to THIS repo via the submodule.

## Working with the author

- **Work on a branch and propose changes as pull requests.** Never push to `main`, merge, delete, or force-push without the author's explicit go-ahead.
- **The writing is the author's scholarship.** Suggest changes and explain them; never silently rewrite their prose. When you draft new text, say that you drafted it.
- **Ask before acting outside this repository** (other repos, services, accounts), and say what you will do first.

## Constraints

- **Run `devtools::check()` before committing R-side changes** if you've touched `R/` or `DESCRIPTION` or `tests/`. R CMD check failures are blocking.
- **Don't commit `_book/` or `.quarto/`** under `ui/www/` — those are build artifacts; they're in `.gitignore`.
- **If `raw/manuscript/LOCKED.md` exists in the linked app repo, it governs.** The manuscript beside it is the author's finished dissertation, imported as authoritative v1.0. Chapter work here extends it — never regenerate, restructure, or replace it. Where that manuscript and anything in this package disagree, the manuscript wins.
- **Don't commit secrets.** No API keys; no institutional credentials.
- **Never put identifiable personal data in git** (participant data, names with addresses, IDs). Analysis data that identifies people stays out of this public-by-default repository.
- **Public repository + unpublished work = warn first.** If this repository is public and holds unpublished chapters or results, tell the author before pushing and show them how to make it private (Settings → General → Danger Zone → Change visibility).
